# Bike-MRT

Fastest door-to-door commute planner for a **Brompton + MRT/LRT** in Singapore. Pick a start and a destination and it finds the best mix of cycling and trains, including trips like *cycle → MRT → cycle → MRT → cycle*, and shows:

- total time, cycling km/minutes and rail minutes,
- every leg on a map (cycle routes along real roads and park connectors, rail along the real track),
- the MRT/LRT lines, stations and transfers,
- a Google Maps cycling link for each cycling leg,
- start from your **GPS location** (the 🎯 button), a searched address, or a pin dropped on the map.

Everything runs **in your browser**: there is no backend. It is a static site that can be hosted for free (GitHub Pages) and installed on a phone as an app (PWA: open the site, then "Add to Home Screen").

## How it works

1. **Bike router** (`frontend/js/router.js`): Dijkstra over a compact Singapore road graph exported from OpenStreetMap, with a Brompton speed cap (16 km/h), a preference for cycleways and quiet roads, and one-way rules.
2. **Planner** (`frontend/js/planner.js`): a shortest-path search over a combined graph of bike and rail states. Switching mode costs fold/unfold and waiting time, and transfers cost extra, so any number of bike ↔ rail alternations can come out of it. It returns the fastest plan plus lower-cycling alternatives.
3. **Data** (`frontend/data/`) is generated by the scripts below from the OSM extract. Rail times are estimates from distance (not timetables).

## Run locally

```
frontend> python -m http.server 8000     # then open http://localhost:8000
```

(or run `start.bat` on Windows). Map tiles and address search need an internet connection.

## Rebuild the data

Needs Python 3.11+ (`pip install osmium numpy`) and Node 20+. Download `Singapore.osm.pbf` from [BBBike](https://download.bbbike.org/osm/bbbike/Singapore/) into `data/`, then:

```
python extract_stations.py     # MRT/LRT station positions       -> data/stations_raw.json
python build_mrt.py            # stations + links + travel times -> data/stations.json, mrt_edges.json
python build_shapes.py         # snap links onto real track       -> data/mrt_shapes.json
python export_bikegraph.py     # compact bike graph               -> frontend/data/bg_*.bin
copy data\stations.json data\mrt_edges.json data\mrt_shapes.json frontend\data\
node build_matrix.mjs          # station-to-station cycling times -> frontend/data/bike_matrix.json
python compress_data.py        # gzip the graph for publishing
```

Bump `VERSION` in `frontend/sw.js` after changing data so installed apps refresh their cache.

## Deploy

Pushing to `main` publishes `frontend/` to GitHub Pages through `.github/workflows/pages.yml`.

## Limitations

- Train times are estimates; there is no live disruption, crowding or timetable data.
- Cycling routes come from OpenStreetMap and can differ from what is legal or comfortable on the ground. Always check the route on the map.
- Fold-and-wait, unfold and transfer times are adjustable in Settings.
- Not affiliated with LTA, SMRT, SBS Transit or Google.
